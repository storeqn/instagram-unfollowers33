# Instagram Unfollowers Pro

تطوير للموقع الأصلي المبني بـ HTML/CSS/JavaScript دون خدمات خارجية أو مكتبات تشغيل. يبقى نشر GitHub Pages على المسار الحالي `/instagram-unfollowers33/`، ولا يتغير الفرع الرئيسي حتى دمج PR.

## الاستخدام

1. صدّر بيانات Instagram بصيغة JSON، وارفع جميع أجزاء followers وملف following ثم اضغط تحليل الملفات.
2. اضغط بدء المراجعة. يُستخدم رابط HTTPS الرسمي للحساب، ليتعامل معه نظام التشغيل كرابط Universal Link حيث يدعمه.
3. نفّذ قرار المتابعة يدوياً داخل Instagram ثم ارجع. الحساب المفتوح لا يُعتبر مكتملًا تلقائياً. اضغط «تم إلغاء المتابعة» أو «احتفظ بالمتابعة» أو «تخطي» أو «تمت المراجعة» لتسجيل قرار وتاريخ.
4. عند العودة يبقى الحساب الحالي نفسه ولا يحدث فتح أو انتقال تلقائي. بعد قرار صريح ينتقل الاختيار إلى الحساب غير المكتمل التالي. خيار «فتح التالي بعد تأكيد القرار» يستعمل نقرة القرار نفسها لفتح الرابط المطابق؛ الافتراضي الفتح اليدوي، ولا توجد مؤقتات.
5. الأقسام والبحث والفرز مستقلة عن طابور المراجعة. إعادة للقائمة تمسح قرار ذلك الحساب وتعيده للمراجعة.

## iPhone والتثبيت

افتح الموقع في Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية ← إضافة. يعمل manifest بمسارات نسبية ووضع standalone. زر التثبيت يعرض التعليمات أو طلب المتصفح المتاح. بعد التحميل الكامل، يخزن Service Worker ملفات الواجهة للعمل دون اتصال؛ فتح Instagram يحتاج اتصالاً. لا تحديث إجباري أو حذف لسجل المراجعة عند ترقية الكاش.

روابط Instagram الرسمية وحدها مستخدمة؛ لا scheme غير موثق أو API أو جلب صور شخصية. تظهر صورة رمزية محلية لأن التصدير لا يضمن صورة صالحة. اختيار فتح التطبيق يعود إلى iOS وإعدادات المستخدم وتثبيت Instagram، وقد يظل الرابط في الويب. لا يمكن اكتشاف نجاح فتح التطبيق أو إلغاء المتابعة. PWA لا يغير هذه القيود. رابط ويب احتياطي مباشر يفتح بطلب المستخدم فقط. تجنّبنا تحويلات متكررة وفتح النوافذ تلقائياً.

## الخصوصية والحفظ

المعالجة محلية؛ لا تحليلات ولا رفع للملفات ولا كلمات مرور. يستخدم سجل محلي واحد في localStorage مع تحقق من البيانات والتعامل مع أخطاء الحفظ. الاستيراد يغير القائمة الحالية ويحتفظ بتاريخ الحسابات حتى لو لم تعد في القائمة. النسخ الاحتياطي يشمل القائمة والتقدم؛ يُدمج أحدث قرار لكل حساب، وتبقى القائمة الحالية إن وُجد استيراد سابق. لتسوية قرار بعد استعادة نسخة قديمة، استخدم «إعادة للقائمة».

لا يضمن المتصفح بقاء التخزين إلى الأبد: مسح بيانات Safari، التصفح الخاص، ضغط المساحة، أو إزالة التطبيق قد تفقده. صدّر نسخاً دورية، واستوردها عند الانتقال من Safari إلى التطبيق المثبت إذا كان التخزين منفصلاً. يرفض التطبيق استبدال سجل تالف بصمت؛ استورد نسخة صالحة لاستعادته. لا تفتح جلسات مراجعة متزامنة، وتُلتقط تحديثات النوافذ الأخرى بأحداث storage.

تقبل الملفات الفارغة الصحيحة وتُرفض الأشكال غير المدعومة. يتم تجاهل السجلات الناقصة مع عداد، وإزالة التكرارات وتوحيد حالة الاسم. الحد 50MB لكل ملف؛ تُقرأ الأجزاء بالتسلسل. القائمة تعرض 50 عنصراً فقط في الصفحة، والمقارنة خطية باستخدام Set.

## الملفات والتشغيل

- `index.html`, `styles.css`: واجهة RTL متجاوبة وتعليمات التثبيت.
- `core.js`: تحليل الصيغ والمقارنة والتحقق من النسخ الاحتياطية.
- `app.js`: جلسة المراجعة والحفظ والبحث والنسخ الاحتياطي.
- `manifest.webmanifest`, `sw.js`: التثبيت وكاش الواجهة.
- `logo.svg` وأيقونات PNG: شعار أصلي متجه لحسابين وسهم وعدسة، دون قص. لم تصل صورة مرجعية في الطلب.
- `tests/`: اختبارات البيانات وسيناريوهات المتصفح.

شغّل `python -m http.server 8000` ثم افتح localhost. لا توجد خطوة بناء أو تبعيات إنتاج.

التحقق: `npm test` و`npm run check`. اختبار المتصفح يتطلب Playwright وChromium: `node tests/browser.cjs` والخادم المحلي على 8000. اختبارات المتصفح تستخدم Chromium بمقاس iPhone؛ ليست إثبات توافق Safari الحقيقي.

## حدود الاختبار اليدوي

قبل الدمج، جرّب على iPhone فعلي: Universal Link مع Instagram مثبت وغير مثبت، الرجوع من التطبيق/ويب، Safari ووضع الشاشة الرئيسية، الفتح الاختياري بعد تأكيد القرار، إعادة تشغيل الهاتف واستئناف السجل، وتثبيت التطبيق. جرّب Android حقيقياً أيضاً. لا تستطيع اختبارات سطح المكتب إثبات سماح iOS بفتح تطبيق خارجي.


## إصلاح الهوية والروابط — الإصدار 1.1.0

عيبان قابلان لإعادة الإنتاج في الإصدار السابق:

- كان `extract` يفضّل `value` حتى لو كان `href` يشير إلى اسم آخر، ويستخدم `title` وحده كهوية. هذا قد يحوّل اسماً ظاهراً صالحاً شكلياً إلى حساب مختلف. الآن يُفحص كل عنصر في `string_list_data` وتُعزل السجلات المتعارضة أو غير الصالحة. لا تُستخدم `title` أو حقول ID كمصدر للهوية. يقبل المحلّل `value` الصحيح منفرداً، أو مسار ملف شخصي رسمي صحيح في `href`، أو الاثنين إذا تطابقا بعد التطبيع.
- كانت أحداث العودة تختار حساباً آخر قبل قرار المستخدم، مع خيار لفتحه فوراً. الآن لا تختار أحداث visibility/pageshow/pagehide حساباً ولا تفتح رابطاً؛ القرار الصريح وحده يسجل الحالة والتاريخ ويختار التالي في عملية حفظ واحدة.

الرابط الوحيد الذي يُبنى للفتح هو `https://www.instagram.com/USERNAME/`. تُرفض مسارات المنشورات والقصص والأجزاء الزائدة والروابط غير الرسمية وHTTP وبيانات الدخول داخل URL. تُزال المسافات الخارجية و`@` وعلامات اتجاه النص الخارجية فقط؛ لا تُحذف أحرف داخلية لإنشاء اسم مختلف. الأسماء الرقمية الخالصة تُستبعد احترازياً لاحتمال كونها معرفات (قد يستبعد ذلك اسماً رقمياً حقيقياً، وهو أفضل من تخمين هويته). لا تعتمد عملية الفتح على أي URL قديم مخزن في التصدير. قبل كل فتح، تُطابق هوية البطاقة والقائمة والحفظ والرابط؛ أي اختلاف يمنع الفتح.

القوائم القديمة لا تُحذف ولا تفقد قراراتها، لكنها تحتاج إعادة استيراد للتحقق بالمحلّل الجديد قبل الفتح. لا تُنقل القرارات من اسم إلى اسم آخر، لأن علاقة إعادة التسمية غير متاحة. إذا كانت الملفات كلها غير موثوقة يُرفض استبدال القائمة. عند استبعاد بعض السجلات تظهر رسالة نتائج جزئية لأن استبعاد متابع قد يغير نتيجة المقارنة. استيراد جميع أجزاء المتابعين ضروري.

ملخص التحقق يعرض الأسماء الفريدة والتكرارات والسجلات الناقصة والمتعارضة وغير الصالحة وأي اختلاف في الأعداد المتاحة. لا يحتوي JSON القياسي عادةً على إجمالي مستقل موثوق أو تاريخ توليد التصدير؛ لذلك لا يستطيع الموقع إثبات اكتمال الأجزاء أو مطابقة عدد التطبيق الحالي. يفحص العدادات الداخلية وأي `count`/`total_count` صريح، ويستخدم تاريخ تعديل الملف وعمر الاستيراد كمؤشرين فقط. تواريخ `timestamp` داخل السجلات هي أوقات العلاقات وليست تاريخ التصدير.

زر «الإبلاغ عن رابط خاطئ» ينسخ تقريراً محلياً فقط، لا يرسل بلاغاً: الإصدار والعدادات وأعلام تطابق الرابط والاسم وصلاحية البيانات. لا يتضمن التقرير أسماء مستخدمين أو روابط أو أسماء ملفات أو محتويات JSON أو سجلات القرارات أو معلومات المتصفح. يمكنك مراجعته قبل مشاركته. عند منع الحافظة تظهر نافذة بنص قابل للتحديد والنسخ على Safari. «نسخ اسم المستخدم» ينسخ الاسم صراحة بطلب المستخدم؛ «فتح في المتصفح» رابط HTTPS مباشر في سياق جديد، لكن قرار نظام iOS بفتح تطبيق خارجي لا يمكن فرضه أو التحقق منه.

تغيّر الأسماء أو حذف الحساب أو إعادة استخدام الاسم لا يمكن كشفه يقيناً من تصدير قديم. لا يتبع الموقع تخمينات لاسم بديل. استخدم تصديراً حديثاً وتحقق من هوية الحساب داخل Instagram قبل قرار المتابعة. لا يوجد اختبار آلي يثبت الحساب الذي يعرضه تطبيق Instagram نفسه.

### الاختبارات في هذا الإصدار

- `npm test`: 13 اختباراً للصيغ والمصادر المتعارضة والتطبيع والروابط والعدادات والمقارنة وترحيل سجل v1 والقرارات و10,000 حساب.
- `npm run check`: فحص JavaScript؛ لا توجد خطوة build في هذا المشروع الثابت.
- شغّل الخادم المحلي `python -m http.server 8000` ثم `npm run test:browser` مع Playwright وChromium متاحين في بيئة التطوير. يمكن تحديد `TEST_BASE_URL` و`CHROMIUM_PATH`. يستخدم الاختبار Chromium، ويعترض روابط Instagram محلياً قبل أي اتصال بالخدمة، ويختبر النقر الفعلي ثم العودة وثبات الهوية والقرارات وإعادة التحميل والنسخ والخصوصية والفلاتر والنسخ الاحتياطي والعمل دون اتصال ومقاسي 390 و1280.
- ملفات `tests/fixtures` عينات اختبار مصطنعة ذات بنى تصدير Instagram المعروفة وأسماء بديلة؛ ليست ملفات شخصية حقيقية من المستخدم. لم تُرفق ملفات المستخدم المسببة للمشكلة، لذلك لا ندّعي إعادة إنتاج ملفه الشخصي بعينه.
- يظل التحقق على iPhone/Safari الفعلي ضرورياً: فتح التطبيق، الرجوع، الحافظة، الروابط والتثبيت. لا تُثبت محاكاة Chromium سلوك Safari أو iOS 27 أو هوية الصفحة التي يعرضها Instagram.
